# Формат карточек знаний

## Структура файла
Файл состоит из двух частей, разделенных одной пустой строкой:

1. **Заголовок (Metadata)**: Блок метаданных.
   - Однострочное поле: `ключ: значение`
   - Многострочное поле: 
     ```
     ключ:
       значение_строка_1
       значение_строка_2
     ```
     (Отступ ровно **2 пробела** для каждой строки значения).

2. **Тело (Body)**: Текст в формате Markdown, содержащий развернутое знание.

## Поля заголовка
Поля являются динамическими. Мы добавляем их по мере необходимости, исходя из контекста.
Т.е. можно придумывать свои при необходимости.

- `type` (однострочное, рекомендуется): Тип знания (например: *факт, правило, инструкция, концепт, гипотеза, пример*).
- `category` (однострочное, рекомендуется): Тематическая область или путь в системе PARA.
- `title` (однострочное, рекомендуется): Понятный человеческий заголовок.
- `summary` (многострочное, рекомендуется): Краткое резюме сути (1-3 предложения).
- `date` (однострочное, рекомендуется): Дата создания/обработки (`ГГГГ-ММ-ДД`).

## Пример
type: правило
category: Zig/ErrorHandling
title: Обработка ошибок через Error Sets
summary:
  В Zig ошибки — это не исключения, а возвращаемые значения, которые нужно обрабатывать явно.
date: 2026-09-08

В языке Zig используется механизм `error sets`. Вместо того чтобы "выбрасывать" ошибку, функция возвращает тип `!T`...

## Расположение
Создаваемые карточки располагаются в `./Cards/`.
Придумайте имя файлу и перед созданием убедитесь что такого файла еще не существует.
Имена файлов на русском языке.
Старайтесь добавлять лёгкую категоризацию в имя файла через префикс с дефисом,
например: `Mint - Дата установки.md`.
