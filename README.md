# ai-config

Настройка ИИ-агента для проектов с открытым исходным кодом, которые хотят давать
читателям не только код, но и знания: пояснения к решениям, контекст и
структурированные записи о том, как устроен проект и почему.

## Зачем

Открытый исходный код отвечает на вопрос «что сделано», но редко объясняет, почему
выбран именно такой путь и какие знания нужны, чтобы вникнуть. Читателю без нужной
подготовки и свободного времени приходится разбираться в коде без объяснений рядом,
а код без текстовых объяснений бесполезен именно для такого читателя. Это и есть
ключевая идея проекта: знания нужно вести наряду с кодом.

Поэтому агент здесь настроен так, чтобы проект мог вести эти знания: сопровождать
изменения пояснениями и собирать карточки знаний — короткие структурированные записи,
объясняющие, что сделано и почему.

Сами настройки выложены открыто, чтобы их можно было обсуждать: для чего нужен тот
или иной блок системного промпта, помогает ли он, — и делиться найденными инструментами
(маленькими инструкциями) и скилами (большими инструкциями).

## Формат карточек знаний

Знания по проекту ведутся карточками: одна тема — один файл в `Cards/`. Формат описан
в `.agents/rules/knowledge_card.md` — путь проектной копии повторяет расположение
файла в домашней директории. Чтобы этот файл участвовал во всех проектах, его нужно
положить в домашнюю директорию `~/.agents/rules/`.

Формат намеренно похож на формат email-писем: заголовок с
полями-метаданными, одна пустая строка, затем тело. Такой формат выбран заранее под
развитие: в заголовок можно добавлять новые поля, например теги, не трогая тело, а
собранные карточки впоследствии разбирать парсером и строить визуальное представление
знаний в виде иерархии или графов.

## Участие

Смотрите `Cards/` и описания настроек, вопросы и замечания — через issues, свои
инструменты и скилы — через pull request.

## Как это работает на примере opencode

[opencode](https://opencode.ai) — агент с открытым исходным кодом для работы с кодом
в терминале. Вот как подключить файлы с инструкциями к его системному промпту.

1. Установите opencode:

   ```bash
   curl -fsSL https://opencode.ai/install | bash
   ```

   либо через npm: `npm i -g opencode-ai@latest`.

2. Откройте конфигурационный файл. Глобальный лежит в
   `~/.config/opencode/opencode.json` и действует на все проекты; настройки конкретного
   проекта — `opencode.json` в его корне — дополняют глобальные.

3. Добавьте поле `instructions` — список путей к файлам, которые нужно подгрузить в
   системный промпт:

   ```json
   {
     "$schema": "https://opencode.ai/config.json",
     "autoupdate": false,
     "instructions": [
       "~/.agents/rules/*.md",
       ".agents/rules/*.md",
       ".agents/memory/*.md"
     ],
     "default_agent": "Code",
     "compaction": {
       "auto": false,
       "prune": false
     }
   }
   ```

Строка со `$schema` — ориентир; из полей мы добавляем `instructions`, `default_agent`,
`autoupdate` и `compaction`. Первый шаблон в `instructions` разворачивает `~` в
домашнюю директорию и подключает файлы правил из неё во всех проектах: чтобы правила
и формат карточек этого проекта действовали везде, скопируйте файлы из `.agents/rules/`
в свою домашнюю папку `~/.agents/rules/`. Второй — локальные правила, специфичные для
текущего проекта, — это тоже полезно. Третий подключает заметки памяти проекта,
созданные по правилу, описанному в `memory.md`.

Таким образом мы получаем агента, который знает, как создавать карточки знаний, и куда
складывать информацию по команде «запомни что...» для последующих сессий.

Поле `autoupdate: false` отключает автообновление самого opencode. Поле `compaction`
с `"auto": false` и `"prune": false` отключает автоматическую компактизацию: при
заполнении контекста история сессии не сжимается, и старые выводы инструментов
не обрезаются.

Содержимое найденных файлов opencode читает и вставляет в системный промпт каждой
сессии с пометкой `Instructions from: <путь>`.

Файл `AGENTS.md` в корне проекта opencode подключает даже без поля `instructions` —
поэтому инструкции этого репозитория начинают действовать сразу после его открытия.

Роль `Code.md` в проекте лежит в `.opencode/agents/`, оттуда opencode читает роли
локально; чтобы она действовала во всех проектах, скопируйте файл к себе в домашнюю
папку `~/.config/opencode/agents/`. В этой папке можно создавать свои системные промпты
наряду с двумя стандартными, уже встроенными в opencode, — Plan и Build: это позволяет
написать системный промпт на русском языке и полностью им заменить стандартные. Но
opencode всё равно ещё докинет несколько промптов по использованию инструментов —
редактирования файлов, работы с MCP — на английском. Поле `default_agent: "Code"` из
примера назначает роль `Code` агентом по умолчанию.
